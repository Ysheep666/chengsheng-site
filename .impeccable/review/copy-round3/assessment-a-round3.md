## 表格的实际证据

三种宽度的 Playwright 浏览器可访问快照均包含：

- table “四句校样示例”；两个 rowgroup。
- 四个 columnheader：句、角色、校样文字、状态。
- 四个 rowheader：1、2、3、4；每行三个 cell 分别对应角色、校样内容和状态。
- 第三句具备命名 textbox，值为“门没关严。”。

源码/DOM 同时确认列头 `scope=col`、行头 `scope=row`，table 描述关联 `demo-label`，textarea 描述为 `demo-feedback demo-length demo-state`。320px 的状态列头 `clip-path: inset(50%)`，未设置 aria-hidden，也未 display:none；浏览器快照依然包含 columnheader “状态”。该宽度状态仍位于第三列下一行，输入宽实测 **188px**。

这验证浏览器语义和可访问树，没有运行真实 VoiceOver，因此不把该证据表述为完整辅助技术验收。

## ZIP 延迟 feed 的必要确认

使用独立 context 拦截本地 feed，响应等到 ZIP 点击后才释放。阻止了链接实际导航/下载，只测试页面状态。当前同版本响应为0.0.7；0.0.8仅是有效 JSON 的模拟新版，不是发行声明。

| 场景 | 响应前 | 响应后 |
| --- | --- | --- |
| ZIP 点击后返回0.0.7 | 首屏“正在检查新版”；页脚“已打开 ZIP 下载链接” | 首屏状态清空；页脚仍“已打开 ZIP 下载链接。进度请查看浏览器下载列表。” |
| ZIP 点击后返回模拟0.0.8 | 同上，用户刚打开的是0.0.7 | 首屏状态清空；页脚“下载链接已更新为 v0.0.8。你刚才打开的是 v0.0.7，可重新下载。”；ZIP链接与版本更新为模拟0.0.8 |

两场景页脚反馈仍为 role=status，没有把打开链接写成下载完成。
