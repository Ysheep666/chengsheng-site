# 成声网站重做：同类网站调研与实施依据

调研日期：2026-09-30。目标是让第一次来的作者理解「本机有声书校样台」，看懂按句返修，下载正确的 Apple 芯片 Mac 安装包，并顺利开始使用。

本文件记录首次重实现时的调研与实施。2026-10-01按用户纠正，整块底部安装下载区及复制/校验工具已删除，必要的安装交接只留在FAQ内；当前页面与文案决定以[后续全站审查](2026-10-01-copy-audit.md)为准。

## 调研方法

访问五个产品的官方产品页，读取标题、行动入口、内容顺序与帮助内容；通过 Chromium 在 1440 × 1000 下抓取首屏，检查真实排版。另阅读 ElevenLabs 的 Studio 操作文档和 Superwhisper 的安装完成页。原始截图与 DOM 提取结果已归档到 [references/](references/observations.json)，参考网站截图用于调研，成声页面的界面全部由自己的 HTML/CSS 实现。

调研范围是公开产品页、下载／安装页和官方说明；没有把登录后未经体验的应用流程当作亲测结果。以下「观察」是来源事实，「成声采用的做法」是结合本产品的设计判断，未进行转化率实验。

这些产品分成两组：ElevenLabs、Descript、Speechify 说明文本与音频制作流程；Superwhisper、VoiceInk 说明本机 Mac 工具的下载和安装。后者不是有声书制作的直接竞品，借鉴范围限定在分发和解释本机能力。

## 五个网站的结构分析

### ElevenLabs：先给创作结果，再让编辑器证明

公开页的结构是首屏创作承诺与试用 → 编辑工具 → 创作者场景 → API → 定价与 FAQ。首屏使用大幅产品画面，使抽象的生成能力落到一个可理解的工作区。成声借鉴的是「产品机制本身是证据」：章节、角色、校样与状态需要直接可见。[首屏证据](references/elevenlabs.png)、[官方产品页](https://elevenlabs.io/studio)。

官方说明把章侧栏、选中文字的生成、文字或音色修改后失去完成状态、按章或项目导出连起来。这说明长内容工具需要交代局部修改对成品的影响。成声将自己的「一句是最小返修单位」做成可操作示意；具体交互及状态取自成声产品，不推断两者实现相同。[Studio 官方说明](https://elevenlabs.io/docs/eleven-creative/products/studio)。

### Descript：用文字任务解释声音工具

页面先说明文字转声音，然后给操作步骤、输入文字后的结果、更多能力、证明与 FAQ。标题、下载／开始入口和正文有明确优先级；任务解释先于完整功能目录。成声据此用「导入书稿 → 切章配声 → 逐句校样 → 导出」组织四步，而非让第一次来的作者理解一串模型参数。[首屏证据](references/descript.png)、[官方工具页](https://www.descript.com/tools/text-to-speech)。

成声没有可核验的客户墙和评价，信任来源改为实际下载地址、明确的架构要求、失败回退和文件校验。这里是我们根据产品阶段作出的选择，不是对同行商业效果的判断。

### Speechify：统一行动，并在能力展开前给体验入口

公开页在多处使用进入 Studio 的行动，先呈现创作套件与体验，再展开音色和不同规模的使用场景。访客读到不同段落时仍能回到同一个开始路径。成声采用同样的行动一致性：两处主下载都指向同一当前 DMG，页内导航和示意只承担解释任务。[首屏证据](references/speechify.png)、[官方 Studio 页](https://speechify.com/studio/)。

成声是专门制作有声书的本机工具，展示章节和句子比复制套件式的能力总览更适合。网页演示明确不生成音频，让读者了解操作而不误解为在线制作器。

### Superwhisper：把下载选择变成安装成功

产品主页与下载页分工：主页解释收益，下载页负责平台、架构、版本和文件入口；安装完成页继续说明打开 DMG、拖入 Applications、启动应用。下载是路径的一步，后面的帮助也要在当下能找到。[首屏证据](references/superwhisper.png)、[官方下载页](https://superwhisper.com/download)、[安装说明](https://superwhisper.com/download/thanks)。

成声把这条路径留在同一页：芯片要求 → 芯片自查 → 下载 → 安装三步 → 第一次出声指南。手机访客可以保存安装包或复制地址，平台限制紧邻行动。高级 ZIP／SHA-256 放到折叠区，首次安装优先看到 DMG。

### VoiceInk：收益、真实使用场景和处理边界一起解释

页面从用户收益进入，接着展示跨应用使用场景，再说明购买方式、FAQ 和隐私；Mac 下载入口明确。FAQ 说明默认本机处理和可选云端能力，边界不只藏在政策页。成声采用这种就地解释，把「工程在本机」与「远程模型收到相关文本」放在同一个段落中。[首屏证据](references/voiceink.png)、[官方主页](https://tryvoiceink.com/)。

本机工具的标题与稿面可以安静，重要限制仍需要可读。成声用宋体表现书稿，用系统字体说明操作；把手机说明保持在可读字号，不以缩小字来容纳所有界面元素。

## 对原网站的判断

原网站的「改一句，听一句」和校样纸具有产品辨识度，但一个短下载台没有充分回答新访客的问题：这是什么工具、如何完成一本书、是否要配置模型、DMG 与 ZIP 的区别、这台电脑能否运行、清单失效时怎么办。最近归档的 28/40 是历史上下文，不直接用作本轮独立评审的评分依据。

## 实施决定

1. 首屏直接写出「书稿 → 有声书」的结果，保留按句返修的产品核心。使用一个直接下载入口和一个指向操作演示的辅助入口。
2. 用 HTML 实现可编辑的校样示意，不用 AI 位图代替文字界面。书名与句子属于示例，状态演示不调用模型，也不声称产生真实音频。
3. 用四个真实制书步骤说明完整流程，在开始前说明模型配置。流程数字用于表达顺序。
4. 以亮宣纸、松烟文字、朱红编辑状态延续产品品牌。首屏展示清楚的稿面；深墨色段落承载本机工程和模型边界。宋体用于书稿和标题，无外部运行时字体请求。
5. 加入安装说明、平台判定帮助、可复制的下载地址、ZIP 备用包、SHA-256 核对和常见问题。高级校验默认折叠。
6. 保留 GitHub Pages 静态部署、现有 JSON 更新协议和发布脚本依赖的精确 HTML 标记。失败时保留 HTML 中的有效下载入口，无 JavaScript 也能下载和阅读帮助。

## 评审约定

按 impeccable 的 Nielsen 十项启发式，每项 0–4 分，总分 40。本页的下载、可编辑示例和核对工具让十项都有实际评审对象，不用 n/a 调整分母。分数来自独立的设计评审，另以浏览器、检测器、可访问性、发布脚本兼容性检查补充证据。先审查、记录问题，再批量修复并复审；用户要求的完成线为至少 36/40。

不得通过删掉评分项、改变分母、加入无关快捷键或虚构用户证言获得更高分。不得为追求满分破坏产品事实。
